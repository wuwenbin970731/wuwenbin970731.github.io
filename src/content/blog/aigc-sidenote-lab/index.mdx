深度技术文章常见的问题是：正文需要讲清楚主线，但读者又会在某些符号、假设、工程细节上停下来。
边注适合处理这种“重要，但不该打断叙事”的信息<Sidenote n={1}>边注和脚注不一样。脚注通常把读者带到文末，边注则留在当前视线附近，更适合技术解释。</Sidenote>。

## 一个例子：从去噪到生成

以扩散模型为例，主线可以写得很简单：训练时逐步给样本加噪，生成时学习把噪声一步步还原成数据。
如果要补充数学符号，可以放到边注里<Sidenote n={2}>例如 $x_t = \alpha_t x_0 + \sigma_t \epsilon$ 表示在时间 $t$ 的带噪样本，其中 $\epsilon \sim \mathcal{N}(0, I)$。</Sidenote>，这样正文不会立刻变成公式墙。

这种写法对 AIGC 博客很有用，因为很多内容都有两层读者：

- 想先建立直觉的人。
- 想检查细节、公式和工程假设的人。

## 用法

在 MDX 中导入组件：

```mdx
import Sidenote from '@/components/sidenote.astro'
```

然后在正文中直接写：

```mdx
一句主线文字<Sidenote n={3}>这里放补充解释。</Sidenote>继续写主线。
```

桌面端会把批注放在右侧，移动端会把编号变成可点击展开的说明块。

## 我会用它记录什么

我倾向于把边注用于：

1. 论文里的符号解释。
2. 算法推导中容易漏掉的假设。
3. 工程实现里“不写会忘，写进正文又太碎”的细节。
4. 对某个概念的个人理解。

它让文章更像一份带批注的研究笔记，而不是只按线性顺序展开的教程。
